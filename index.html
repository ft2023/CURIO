Abstract

Learning from Feedback, Without Losing the Urge to Explore

Open-ended discovery requires learning from repeated attempts while continuing to explore directions whose value is not yet apparent. Search with a frozen large language model (LLM) can reuse previous solutions in context, but cannot update the model from its successes and failures on the test problem. Reinforcement learning (RL) enables such adaptation; however, strongly favoring high-reward trajectories may suppress low-reward yet potentially promising directions too early.

We introduce CURIO, a curiosity-driven test-time learning framework that complements task feedback with an Intrinsic Curiosity World Model (ICWM). The ICWM learns transitions in the policy's hidden-state representation and supplies prediction-error bonuses at sampled tokens outside the policy's top-$k$ choices. Epoch normalization and an annealed weight regulate their contribution to the policy update.

On six mathematical discovery tasks and single-cell denoising with Qwen3 backbones from 8B to 235B, three-run means improve over a matched task-only RL control on five mathematical objectives, match the best reported performance on Circle Packing, and improve denoising Score and mean squared error (MSE) on both held-out corpora at every tested scale. Relative gains reach 18.3% on Hadamard and 10.8% on denoising Score. Code-diversity measurements show greater structural variation among generated programs, supporting curiosity as a complementary exploration signal for learning in open-ended discovery.

How It Works

A Curiosity Signal Inside the Discovery Loop

CURIO follows the test-time RL discovery loop: a policy expands parents from an archive into rollouts, an evaluator scores them, the archive keeps the better solutions, and the policy is updated on the same problem. On top of the task reward, CURIO learns where the policy is surprising itself and rewards exploration exactly there.

(i) Find Branch Points

During generation, CURIO records which sampled tokens fall outside the policy's top-$k$ choices. These departures from the most likely continuation are the only places where the curiosity bonus is applied.

(ii) Learn an Intrinsic Curiosity World Model

An encoder and forward predictor learn $s_t, a_t \rightarrow s_{t+1}$ over the current actor's last-layer hidden states and token embeddings. Its prediction error marks transitions the policy has not yet learned to anticipate.

(iii) Reward Novelty, Then Anneal

Residuals are normalized per epoch and added to the task coefficient with weight $\eta_\tau$, cosine-annealed to a floor. Setting $\eta_0 = 0$ recovers the task-only TTT-Discover update exactly.

Analysis

More Structurally Diverse Programs

We measure code-level structural variation among generated programs with OpenEvolve's island code-diversity metric, which compares pairs of programs by differences in code length, line count, and character sets. CURIO generally maintains higher diversity than TTT-Discover over training. This is a code-level diagnostic: it does not by itself establish semantic diversity of the underlying constructions.

Ablations

What Makes the Curiosity Signal Work

On Qwen3-14B across six tasks, we vary three design choices of the ICWM. Each panel fixes its reference configuration at 50 on every task, so values above 50 indicate improvement and values below 50 indicate degradation.

Curiosity strength matters

$\eta_0 = 0.3$ is best on the autocorrelation tasks and $\eta_0 = 0.5$ on Erdős, Hadamard, and denoising. The largest weight, $0.8$, underperforms the task-only control on some tasks.

A simple MLP predictor is enough

The default MLP forward predictor is competitive with GRU and Transformer alternatives; the best architecture depends on the task.

Coupling to the evolving policy helps

Reading states from the current actor leads on most tasks, compared with a frozen initial actor or a frozen external LLM.

Get Started

Run CURIO on Your Own GPUs

CURIO runs fully locally: generation on Ray Data LLM (vLLM) and LoRA training on DeepSpeed, with resumable per-stage checkpoints and launchers for single nodes and SLURM clusters. See the repository for setup, the required Ray patch, and all configuration options. 

git clone https://github.com/ft2023/CURIO.git && cd CURIO
source .venvs/curio-runtime/bin/activate

export CURIO_ERDOS_CONFIG=qwen3_8b_2xH100
export CURIO_EVAL_PYTHON=$PWD/.venvs/curio-eval-erdos/bin/python
export CURIO_LOG_ROOT=/path/to/your/log/root

bash tasks/erdos/launchers/single_node/run_all.sh
